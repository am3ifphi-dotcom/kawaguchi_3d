# 外観・階段再照合と表示／歩行モード（2026-09-28）

## 階段の訂正（正面接続）

旧稿は写真の南側階段と設計図の南北の階段記号を、校舎2Fへの**二つの側面直結階段**と誤って同定していた。ユーザー指摘により撤回し、現在はラーニングストリートの軸に沿って西→東へ上る正面階段を仮置き。旧造形（地表から立ち上がる厚い鋸歯状のプリズムを含む）を削除し、薄い段と簡単な手摺りだけを表示する。赤帯・植栽島は市の写真で確認した**別階段の可能性**があるため、正面階段には転用しない。詳細は [`west-circulation-study.md`](west-circulation-study.md)。

正面接続の向きはユーザー指摘に沿うが、x=−29〜−8m、24段、北32.5〜51.5m、植栽の有無、地盤高、竣工後の床境界は未確認。`.scratch/screenshots/front-entry.png`で正面から段・上部踊り場・校舎を視認した。モデルが実物に一致した証明ではない。

## X字フレーム

設計資料p.8の**アリーナN南立面の棟間上部に交差線**がある。屋根端に接する2組の額縁状のX字部材を試作し、単独の「屋上のX字フレーム」視点を追加した。校舎南面中央上部にも、同じp.8で読める交差線の候補を細いフレームとして仮表示。実ブラウザの `.scratch/screenshots/roof.png` で形状が見えることを確認した。ただし **棟帰属・図面記号の意味・竣工時の存否・断面寸法は未確認**。写真で確認できないものを「実在装飾」と断定しない。

## 高質感モード（任意）

`src/world/quality.ts` を追加。ボタンON時だけ影付き日照、ACESトーンマッピング、スクリーンスペースAO（SSAO）、手続き的な細粒の色ムラを描画。写真テクスチャの無許可流用ではなく、材質の演出上の仮表現。`EffectComposer`/`SSAOPass`は遅延ロードし、通常モードでは不要な計算をしない。`.scratch/screenshots/quality.png` を実描画し、階段や足元に影・陰影が出ることを確認。ソフトウェアWebGLのヘッドレス環境では非常に低速で、実GPUのFPSは未測定。60fps保証ではない。GPUやドライバによってSSAOが使えない場合は影だけを表示。

## 一人称で歩くモード（屋外試作）

`src/world/walk.ts`。ボタン→ポインターロック、WASD移動・マウス視線・Shift速歩・Spaceジャンプ、Esc終了。重力と床高さのレイキャストにより中央広場の正面階段、東門階段、2F連絡床の**モデル上の段差**を昇降できる。外周壁の横方向レイキャストを簡易衝突として用いる。屋内公開、精密な構造物衝突、バリアフリー経路、測量GL、避難経路の検証は対象外。歩行中に表示される高さは**モデルの仮原点**からの相対値。

Chromium/SwiftShaderでポインターロック取得、正面階段西の歩行開始位置で床高0.0mからのW押下後の位置値変化、Escでロック解除・視点復帰を確認。ロック到達前のOrbitControls更新により空中から落下していた開始位置のバグを修正。全段を歩いて昇れるかは実ブラウザで通し検証できていない。`npm run audit`では現行のモデル階段メッシュにレイを当て、正面階段の西→東3点で段上床高さが約0.33→2.0→3.83mと昇ることも確認。品質モードと同時に操作する実機GPU検証は未了。高質感を標準に戻してから歩行すると、この検証環境では操作しやすい。

## まだ整合しない重要要素

中央広場とアリーナ通りには、公式写真に明瞭な**曲線の上階歩行デッキ**、造作ベンチ、円形植栽、複雑な舗装表示があり、現行モデルはその平面や接続を十分に再現できていない。学校名サインの東端S/N割当も写真方位が未校正。現時点で「すべて完全再現」は主張できず、図面にある通り芯と竣工時の階段・外構の詳細図、屋上Xの鮮明な現況写真が必要。これは不足項目を明記した外観スタディである。
