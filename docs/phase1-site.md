# Phase 1 — 敷地・周辺GIS基盤（2026-09-28）

## 承認と設計資料優先ルール

ユーザー決定：Vite + Vanilla TypeScriptを採用し、実寸形状は**実施設計図優先**。したがってこの段階で造形済みなのは入力JSONのLOD1**調査表示**に限る。JSONから窓・道路・敷地境界・室形状は復元できない。将来の校舎造形には図面の室外形/階高を使い、GISを地理的配置と周辺建物に使う。JIA面積差は資料のスコープ/時点の差として留保。

## PDF × JSON：識別可能になった棟の「候補」

図面p.3の東西並び・p.2の建築面積と、提供JSONのring面積・相対位置・hを突合。たとえば西側アリーナSに相当しそうなIDは `bldg_201a8894…`（JSONポリゴン面積**4,389.9㎡**、h=20.2m、x=−122.78～−30.18m、北距−10.03～44.96m）で、図面計画面積4,447.77㎡との差約58㎡。東側校舎と推定される3ポリゴンは `bldg_4cf7907f…`（2,112.7㎡、h21.3）、`bldg_44f5071e…`（1,722.8㎡、h22.1）、`bldg_2d60618f…`（1,719.4㎡、h20.6）。3つ合計5,554.9㎡で図面の校舎棟建築面積5,944.55㎡と同一視できない（約389.7㎡差）。北西側2件 (`bldg_b01d7688…`, `bldg_0c732e20…`) はN棟の可能性。**GIS原本が未確認で、図面と測地基準点の精密重ね合わせをしていないため、対応・高さはすべて推定。LOD1は校舎の完成形ではない。** マスターリストにはID・範囲・確度を格納。

JSON全体は建物ポリゴンのみ。画面では原点から300mの円に辺が触れるリング、正高さ、閉合・非退化の輪郭だけを表示する。欠測208件を勝手に3mに置換しない。学校候補7件は琥珀色の調査レイヤーとして区別する。全部の周辺モデルは1つのBufferGeometryに統合してドローコールを抑える（別に学校候補1メッシュ）。高さは仮の基準面 y=0 からの立ち上げで、GLや海抜ではない。

## 画像の追跡と実際に閲覧できたもの

学校サイト4アルバムにある**31枚すべての個別画像ファイルID**を[写真URL台帳](../data/photo-inventory.json)に記録。学校ページの `photo_modal` を辿り、`files/download/{ID}thumb` の配列順とキャプションを照合した。本文に埋め込まれた画像はPhase 0文書に列挙済み。

学校サーバーへこの実行環境から直接TLS接続すると切断される。31件のURLを個別にリモート・テキストリーダーに渡して試した結果、21件は**機械生成のごく粗い画像説明だけ**が返り、10件は403で閲覧不可だった。説明文には誤認例があるため写真を見た証拠として扱わず、寸法根拠にしない。画像そのものを全31枚取得することはできなかった。検索エンジンの画像キャッシュから**別の公式画像の実画素**を複数確認した（画像は権利未確認のためリポジトリに保存しない）：

- [学校公式の校舎外観画像](https://kawaguchicity-hs.ed.jp/about/facility/building)：東側の左右に立つ淡色のボリューム、その間の低い半透明膜屋根、側面の濃色水平庇。入口側はセットバックしている。2015年イメージ図p.1と入口構成の方向性は整合するが、色・詳細は竣工写真優先。
- [学校公式のラーニングストリート・アルバム表紙](https://kawaguchicity-hs.ed.jp/p/photo_albums/photo_list/224/52?frame_id=439) と [川口市の内部写真2点](https://www.city.kawaguchi.lg.jp/soshiki/01120/050/2/46354.html)：膜材下面に繰り返す細い横架材、コンクリート打放しと白い凹凸壁、緑/青/赤の突出部、グレーの舗装に白いライン、植栽箱・複数階渡り廊下が確認できる。**写真のピクセル寸法は建築実寸に変換しない**。
- [学校公式のグラウンド空撮](https://kawaguchicity-hs.ed.jp/about/facility/ground)：実際のトラックは青系、内部は人工芝、校舎の南側に位置。2015年広報p.2の完成予想図ではトラックが赤系なので、**図の色を竣工色として採用すると写真と矛盾する**。外構色は写真を優先し、モデルではまだ着色していない。
- [川口市のアリーナ棟画像](https://www.city.kawaguchi.lg.jp/soshiki/01120/050/2/46357.html)：N棟小アリーナの木質腰壁と白い露出トラス・ハイサイド窓、S棟4階廊下のコンクリート打放しと黒手摺を確認。窓割り等の寸法根拠は不十分。

学校公式アルバム31枚の**個別画素を全て精査したとはまだ言えない**。台帳のURLは分かったので、ユーザーPCのブラウザでURLを開き原画を渡してもらうか、公式ページがアクセス可能な環境で再取得する。未確認の写真について造形に推測を混入させない。

## Phase 1 の範囲と検証

`npm run dev` でThree.jsのデスクトップ画面を起動。OrbitControls・リサイズ・Stats.js・ミニマップ・表示切替を実装。ユーザー提供の2タイルはオフで起動し、明示的にオンにした時だけ表示。緯度経度からWGS84局所楕円近似で中心位置を合わせるが、元タイルの出典/Web Mercator/画像時点は未照合、南半分の画像は存在しない。地形と道路は地理参照付きDEM/ベクターがないため未実装。y=0フラット面は測量GLでないことを画面に明記。高さ・構造の確定校舎メッシュ/膜屋根はPhase 2・3の承認後。

## 性能の確認状況

`npm run build`（TypeScript型検査 + Viteビルド）成功。動的描画の建物は2つのまとめたMesh（周辺/候補）で、条件外リングは除外。**60fpsの実測は未実施**；現場PCでStats・renderer.info・メモリを確認後に主張する。バンドル警告はJSON全3,070棟を初期JSに同梱したため約1.1MB。この後の最適化では300m周辺だけを事前抽出した監査可能な生成物を使い、出自IDを保持する。
